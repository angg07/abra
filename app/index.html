Record flow

A browser with the Playwright Inspector opens on your desktop. Click through the flow, then close the window: the script is ready to copy, save as a test, or hand to the AI as a route map.

Saved tests

Replayed with plain Playwright, no AI: fast, no quota used, the same result every time. Tick several to run them as one suite.

Workflows

Blocks chained in one browser (AI tasks, data extraction, checks, saved tests, loops, API calls), so a login or an open page carries over.

AI blocks use the AI chosen on Run AI.

History

Every AI run, replay and workflow, with its steps, errors, video, PDF guide and report.

Settings

Shared by every project: AI providers, secrets, environments, schedules, PDF guides, recording and users.

API keys are stored in the .env file on this computer and are never shown again. Leave the field empty to keep the key that is already saved.

Secrets

Tick the projects that may use each secret: a secret works only in those projects' runs. Write {{NAME}} in your instructions, for example {{ADMIN_PASS}}. The real value is typed straight into the browser; the AI only sees the name. Saved tests read it from .env.

Use test accounts, not production credentials. Masking is best-effort: values are hidden from what the AI reads, but an AI that deliberately runs a script to spell out a field could still see one, and secrets typed into ordinary text fields show in videos.

An environment is a set of test values, one per line as name=value. Use them as {{name}} in instructions, URLs and tests. Use one environment per stage (local, staging) with one address per app, e.g. appUrl=http://myapp.test. Values that are web addresses are special: saved tests replace that address with {{appUrl}}, so the same test runs on any stage.

Production: add an environment with the real addresses (e.g. appUrl=https://example.com) and tick Production. Those host names are then blocked in every test browser, the AI's, replays and npx playwright test, so no test can create data there by mistake. A production environment cannot be picked for a run. Record flow only checks its start address.

Always available: {{today}} {{today+3}} {{today-7}} {{now}} {{random}} {{runId}}, and a date format like {{today|DD/MM/YYYY}}.

Notifications

After each scheduled run you get the result, and on Telegram also the HTML report. Telegram: store the bot token as the secret TELEGRAM_TOKEN and fill in the chat id. Slack: store an incoming-webhook URL as the secret SLACK_WEBHOOK.

Scheduled suites

Saved tests run by themselves at a set time and go through the same queue as your own runs. The app must be running at that time; a run missed by up to 30 minutes still starts.

How the step-by-step PDF guides look, e.g. as tutorials for your users or clients. Applies to guides made from now on.

In Indonesian, step sentences are translated (e.g. "Klik tombol “Login”"); the AI's notes, which are always in English, are left out of the guide.

This size is used for the browser screen during tests and for the video resolution. Applies from the next run.

Serious and critical problems (contrast, missing labels, images without alt text, ...) are listed per page, apart from app errors. Adds about a second per new page.

Visible in the live view, the video and the PDF guide. It adds a small overlay element to the page being tested; turn it off if a test counts elements on the page.

Accounts are made here; nobody can sign up alone. A new account chooses its own password at first sign-in. Admins can do everything; everyone else only sees the projects they are a member of (Projects > Edit > Members). Changes here apply right away.
