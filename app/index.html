      AI providers
      The AI engines a run can use. Pick one per run on the AI page.
      
      
      
      
      
      How it works
        
      API keys go to the .env file on this computer and are never shown again: leave the field empty to keep the saved key. Claude Code uses the subscription you are signed in with; give it a config folder (e.g. ~/.claude-2) to use another account, and add one provider per account.
      
      
      
    
      
    
      
      
      Secrets
      Passwords and tokens for your tests. Write {{NAME}} in instructions; the AI only ever sees the name.
      
      
      Use test accounts, not production credentials.
      
      
      
      
      No secrets yetAdd one, e.g. ADMIN_PASS, then pick the projects that may use it.
      
      
      
      How it works
        
      A secret works only in the runs of the projects you pick. The real value is typed straight into the browser; saved tests read it from .env. Masking is best-effort: an AI that deliberately runs a script to spell out a field could still see a value, and secrets typed into ordinary text fields show in videos.
      
      
      
    
      
    
      
      
      Environments
      One set of test values per stage (local, staging), one per line as name=value. Use them as {{name}}.
      
      
      
      
      
      How it works
        
      Web addresses are special: saved tests replace them with their name (e.g. {{appUrl}}), so the same test runs on any stage.
      
        
      Production: add an environment with the real addresses and mark it Production. Those host names are then blocked in every test browser (the AI's, replays and npx playwright test), so no test can create data there by mistake. A production environment cannot be picked for a run.
      
        
      Always available: {{today}} {{today+3}} {{today-7}} {{now}} {{random}} {{runId}}, and a date format like {{today|DD/MM/YYYY}}.
      
      
      
    
      
    
      
      
      Schedules & alerts
      Saved tests that run by themselves, and where their results go.
      
      
      
        
      Scheduled suites
      
        
      
        
      No schedules yetE.g. run a project's smoke tests every weekday at 07:00.
      
        
        
      The app must be running at that time; a run missed by up to 30 minutes still starts.
      
      
      
      
      
        
      Notifications
      
        
      
          
          
        
      
        
      
        
      Telegram: store the bot token as the secret TELEGRAM_TOKEN. Slack: store an incoming-webhook URL as the secret SLACK_WEBHOOK. After each scheduled run you get the result (and on Telegram the HTML report).

          Edit test
          
      
    
          
    
          
      
          Use '{{today}}', '{{today+3}}', '{{random}}', '{{baseUrl}}/path', '{{ADMIN_PASS}}' or '{{data.column}}' in any string; they are filled in when the test runs. Dates are YYYY-MM-DD unless you add a format: '{{today|DD/MM/YYYY}}'.
          
      
          Check the database after the UI steps (read-only): import { dbQuery } from '../support/db'; then const [row] = await dbQuery('select status from orders where order_no = $1', [orderNo]);. Which database: Projects > Edit > Database, for the environment of the run.
          
      
          Visual check:  at the cursor. The first run saves the screen as the baseline; later runs fail if the screen changed and show expected, actual and difference. Hide changing parts (dates, numbers) with mask: [page.getByText('…')].
          
      
      
      
          
        Files Upload templates and documents this test uses. In the script: setInputFiles('{{file.name}}'). Up to 20 MB each; saved right away.
